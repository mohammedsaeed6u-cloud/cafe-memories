# حدود الأمان الحالية

- مفتاح `SUPABASE_SERVICE_ROLE_KEY` للخادم فقط. جميع مسارات التاجر تفحص `getUser()` وعضوية المنشأة والفرع ثم حالة المنشأة قبل استخدامه. ضيف Supabase المجهول يستطيع تعديل موافقة صوره وإعدادات حسابه بنفسه فقط، ولا يستطيع منح زيارة لنفسه؛ تسجيل الزيارة يتطلب طلب حضور حديثًا من صفحة الفرع وتأكيد الموظف لعملية شراء فعلية. فتح صفحة الفرع عن بُعد ممكن، فلا يُعد طلب الحضور دليل موقع أو شراء؛ ليست هذه حماية قارئ NFC موثّق.
- سياسات RLS لا تسمح للضيف بترقية دوره أو إنشاء صور/زيارات موثقة مباشرة، ولا تسمح لمدير فرع بإدارة المنشأة أو قاعدة المكافأة العامة. صلاحية المدير العام تتطلب عضوية بلا فرع.
- الصور خاصة؛ طلب الوسائط يتحقق من الإذن من قاعدة البيانات في كل مرة ويعيد `no-store`. رفع صورة الختم الجديدة يتطلب زيارة `verified` مطابقة للضيف والمنشأة عبر RPC للخادم فقط؛ الصف المقفل يمنع صورتين نشطتين لنفس الختم، والصورة لا تُنشئ ختمًا. جدول الكروت بلا سياسة قراءة مباشرة للضيف/التاجر؛ `/api/v1/customer/story` يتحقق من هوية الضيف، ثم يقيّد قراءات `service_role` بمعرّف العميل والمنشأة لكل كارت/زيارة/صورة، ويعيد روابط وسائط خاصة فقط و`no-store`. صفحة الطباعة لا تتضمن الصور في HTML الخادم، ولا توجد روابط مشاركة عامة للكارت. يستطيع الضيف حفظ PDF أو طباعة نسخة بنفسه؛ الإذن المسحوب من الشاشة لا يسترجع نسخة ورقية أو PDF سبق إنشاؤه. اقتران الشاشة صالح برمز قصير ثم cookie HttpOnly يحتفظ بسر عشوائي غير مخزّن بصيغته الأصلية في قاعدة البيانات. يُلغى وصول الشاشة عند فصلها.
- الحسابات التجارية تتطلب بريدًا مؤكدًا في Supabase Auth. مسارا Google للمنشأة والعميل منفصلان؛ إنشاء المنشأة عبر Google يتطلب تصريح محاولة حديثًا من صفحة دخول المنشأة، ثم نموذجًا لاختيار اسمها ورابطها بعد التوثيق؛ لا يستخدم اسم الملف الشخصي في Google كاسم تلقائي للمنشأة. ربط Google بضيف له ذكريات يحتفظ بمعرّف Supabase Auth نفسه، ولا يدمج حسابين مختلفين تلقائيًا. رقم التواصل الاختياري في إعدادات الضيف منفصل ومحمي بـ RLS ولا يعتبر وسيلة تحقق أو اكتساب زيارات. الحسابات المحلية القديمة وأرقام PIN وملفات Wallet غير الموقعة أُزيلت. كلمات المرور لا تمر عبر قاعدة بيانات التطبيق أو localStorage.

**ما لم يكتمل بعد:** يجب ضبط حدود معدل الطلبات عند الحافة، واختبار القيود وStorage على مشروع Supabase staging، وإعداد سياسة الاحتفاظ والحذف/استرجاع جلسات الضيف والمراقبة قبل نشر تجاري. [تفاصيل التشغيل](DEPLOYMENT_AND_DATA_MIGRATION.md).
