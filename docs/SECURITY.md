# حدود الأمان الحالية

- مفتاح `SUPABASE_SERVICE_ROLE_KEY` للخادم فقط. جميع مسارات التاجر تفحص `getUser()` وعضوية المنشأة والفرع ثم حالة المنشأة قبل استخدامه. ضيف Supabase المجهول يستطيع تعديل موافقة صوره وإعدادات حسابه بنفسه فقط، ولا يستطيع منح زيارة لنفسه؛ زيارة العميل تتطلب حضورًا حديثًا للفرع وتأكيد موظف.
- سياسات RLS لا تسمح للضيف بترقية دوره أو إنشاء صور/زيارات موثقة مباشرة، ولا تسمح لمدير فرع بإدارة المنشأة أو قاعدة المكافأة العامة. صلاحية المدير العام تتطلب عضوية بلا فرع.
- الصور خاصة؛ طلب الوسائط يتحقق من الإذن من قاعدة البيانات في كل مرة ويعيد `no-store`. اقتران الشاشة صالح برمز قصير ثم cookie HttpOnly يحتفظ بسر عشوائي غير مخزّن بصيغته الأصلية في قاعدة البيانات. يُلغى وصول الشاشة عند فصلها.
- الحسابات التجارية تتطلب بريدًا مؤكدًا في Supabase Auth. مسارا Google للمنشأة والعميل منفصلان؛ إنشاء المنشأة عبر Google يتطلب تصريح محاولة حديثًا من صفحة دخول المنشأة. ربط Google بضيف له ذكريات يحتفظ بمعرّف Supabase Auth نفسه، ولا يدمج حسابين مختلفين تلقائيًا. رقم التواصل الاختياري في إعدادات الضيف منفصل ومحمي بـ RLS ولا يعتبر وسيلة تحقق أو اكتساب زيارات. الحسابات المحلية القديمة وأرقام PIN وملفات Wallet غير الموقعة أُزيلت. كلمات المرور لا تمر عبر قاعدة بيانات التطبيق أو localStorage.

**ما لم يكتمل بعد:** يجب ضبط حدود معدل الطلبات عند الحافة، واختبار القيود وStorage على مشروع Supabase staging، وإعداد سياسة الاحتفاظ والحذف/استرجاع جلسات الضيف والمراقبة قبل نشر تجاري. [تفاصيل التشغيل](DEPLOYMENT_AND_DATA_MIGRATION.md).
