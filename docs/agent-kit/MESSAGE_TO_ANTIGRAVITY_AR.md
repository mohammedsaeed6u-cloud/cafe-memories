## أولاً: استورد الحزمة فقط بأمان

افحص الفرع والتغييرات المحلية واحفظ عمل الفريق بطريقة آمنة قبل الاستيراد. لا تدمج فرع الجلسة كاملاً ولا تعمل reset/clean ولا تغير فرعك لمجرد الحصول على الحزمة. اقرأ الحزمة من GitHub أو اجلب الفرع واستورد الملفات المحددة بعد مراجعة أي تعارض محلي:

- `docs/agent-kit/ANTIGRAVITY_PLAYBOOK_AR.md`
- `docs/agent-kit/LIBRARY_DECISIONS_AR.md`
- `.agents/skills/stampy-task-control/SKILL.md`
- `.agents/skills/stampy-operational-integrity/SKILL.md`
- `.agents/skills/stampy-ui-review/SKILL.md`
- `.agents/skills/stampy-release-evidence/SKILL.md`

راجع التغيير في `GEMINI.md` وأضف مراجع الحزمة إلى تعليماتك الحالية دون محو توجيهات الفريق. لا تفترض أن المهارات تُكتشف أو تُفعّل تلقائياً؛ افتح ملفاتها واقرأها صراحةً. تعليمات البيئة الأعلى أولوية تظل سارية.

## ثانياً: أكد الفهم قبل تعديل التطبيق

اقرأ AGENTS.md وGEMINI.md والحزمة ثم أرسل:
1. الفرع الحالي وcommit وحالة الملفات المحلية.
2. ملخص القواعد الأساسية التي ستلتزم بها.
3. أي تعارض بين القواعد الحالية والحزمة أو الهوية أو عقود المنتج.
4. المهمة الواحدة المقترحة ونطاق الملفات ومعايير قبولها.

لا تبدأ تغييرات تطبيقية أو تثبيت dependencies أو نشر قبل تحديد المهمة والتفويض المناسب.

## ثالثاً: قواعد التنفيذ

- مهمة واحدة محددة في كل شريحة عمل، دون refactor واسع خارج النطاق.
- لا نجاح صوري، ولا demo fallback عند فشل قاعدة البيانات، ولا تجاوز مصادقة داخل التطبيق لإرضاء الاختبارات.
- لا تعتبر موافقة التسويق صحيحة دون قراءتها من مصدرها الحالي الخاص بالمنشأة.
- لا تساوِ إصدار المحفظة بتثبيتها، أو قبول المزوّد بوصول الإشعار.
- افحص صلاحيات الدور والمنشأة والفرع خادمياً، مع حالات الرفض والتزامن والتكرار.
- استخدم مكتبات المشروع الحالية أولاً؛ أي dependency جديدة تحتاج مشكلة واضحة وفحص توافق وقرار.
- لا تغير هوية STAMPY أو قواعد الهاتف والموافقات والختم الترحيبي باجتهاد منفرد.
- لا تمسح عمل الزملاء، ولا تعدل ملفات مشتركة دون تنسيق.
- لا تدّعِ تشغيل وكلاء فرعيين أو مراجعة متصفح أو نشر لم يحدث فعلياً.

## رابعاً: التسليم

قبل التسليم استخدم stampy-release-evidence. أرسل ما تغير، الملفات، الاختبارات والأوامر ونتائجها الفعلية، وما لم يُختبر، وأي متطلبات staging أو جهاز حقيقي. لا تستخدم «جاهز 100%» بدلاً من الأدلة، ولا تغلق مهمة تحتاج تحققاً لم ينفذ.

ابدأ الآن بتأكيد قراءة الحزمة وعرض التعارضات، دون تغيير التطبيق.
