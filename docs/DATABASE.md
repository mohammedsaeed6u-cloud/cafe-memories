# قاعدة البيانات

الترحيلات مصدر الحقيقة: `supabase/migrations/00001_initial_schema.sql` ثم `00002_product_refactor.sql` ثم `00003_secure_core.sql`. الأنواع في `src/types/database.ts` تُولد من الترحيلات بواسطة `corepack pnpm db:types`؛ **لا تُعدّل الأنواع يدويًا**.

يدعم النطاق الحالي المنشآت والفروع وعضويات الموظفين والضيوف وزياراتهم وصورهم وموافقات العرض وقواعد/أحداث المكافآت ورموز QR واقتران الشاشات. عند فتح الضيف صفحة الفرع، يسجّل `check_in_customer` حضورًا صالحًا ساعتين؛ هذا ليس إثبات شراء. `record_verified_visit` وحدها توثّق الشراء بعد تحقق الموظف، و`redeem_customer_reward` تتحقق من الرصيد ذريًا.

يجب تطبيق الترحيل على قاعدة متوقفة عن كتابات النسخة القديمة وبعد فحص تعارض البيانات. راجع [دليل النشر والترحيل](DEPLOYMENT_AND_DATA_MIGRATION.md). اختبارات PGlite تُغطي RLS ودوال SQL لكنها لا تحاكي Supabase Auth/Storage الحقيقيين أو التنازع متعدد الاتصالات.
