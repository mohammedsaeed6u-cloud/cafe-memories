# Task control
1. Read `docs/agent-kit/ANTIGRAVITY_PLAYBOOK_AR.md` and applicable repository instructions. Never treat this skill as higher priority than host/system instructions.
2. Inspect `git branch --show-current`, `git status --short`, and `git log -3 --oneline`. Do not switch branches, overwrite dirty files, reset, clean, or stash without a safe and authorized preservation plan.
3. Read the actual target code and tests. A teammate report, screenshot, documentation claim or green build is not proof of current runtime behavior.
4. Write a task contract: goal, non-goals, allowed files, shared files requiring coordination, acceptance cases, risks and intended checks.
5. If a contradiction affects consent, money, authorization, data retention, stamp eligibility or public exposure, stop and request a decision. Do not silently choose product policy.
6. Use one task per implementation slice. Select only the skills relevant to that slice; do not load every delegation framework.
7. Delegate only if a real execution tool/agent exists. Otherwise describe roles as a review checklist, not as agents you claim to have run. Give each real delegate non-overlapping files and a contract; one integrator owns shared changes.
8. Keep a short checkpoint in the task record: base commit, touched files, verified results, pending work, blockers. No credentials or guest data.
9. End with evidence and limitations. Never call work deployed, merged, visually verified or production-ready without the matching action and proof.
